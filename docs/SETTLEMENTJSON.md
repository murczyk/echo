# Файли населених пунктів у ECHO

## Коротко

`settlements.json` — це довідник назв населених пунктів, їхніх координат і регіонів. ECHO використовує його, щоб упізнати назву населеного пункту в тексті та пов’язати її з місцем на карті.

Нові довідники поділені за регіонами: один JSON-файл відповідає одному регіону. Наприклад, `kharkivska_oblast.json` містить Харківську область, а `kurska_oblast_rf.json` — Курську область РФ. Файли створюються в проєкті `milgeo-rs`; ECHO їх не генерує і не редагує.

## Навіщо обирати файли окремо для кожного AOR

AOR (Area of Responsibility) — це смуга відповідальності. Для різних AOR потрібні різні регіони. Наприклад, для смуги біля Харківщини можуть знадобитися файли Харківської, Сумської, Бєлгородської та Курської областей.

Обмеження довідника потрібними регіонами:

- зменшує кількість помилкових збігів, коли однакові назви існують у різних областях;
- дозволяє врахувати сусідні регіони, якщо AOR перетинає адміністративні межі;
- не змушує кожну смугу використовувати весь загальний довідник.

Для одного AOR можна і зазвичай потрібно вибрати кілька файлів.

## Як ECHO використовує ці дані

У файлі для кожного населеного пункту зберігаються назва, регіон, координати, ідентифікатор та, за наявності, мовний варіант назви. Після запуску ECHO завантажує довідники в пам’ять і готує їх для швидкого пошуку.

Коли система знає AOR повідомлення або імпорту, вона шукає назви лише у файлах, вибраних для цього AOR. Це використовується під час автоматичного розпізнавання локацій у повідомленнях та імпортованих даних, розбору згадок про підрозділи й локації, а також у пошуку населених пунктів та списку регіонів в інтерфейсі.

Якщо AOR не передано або для нього немає окремого налаштування, ECHO використовує набір сервера за замовчуванням із `config.toml`.

Зміна вибору в адмін-панелі застосовується одразу до нових пошуків і подальшої обробки. Вона не переписує автоматично результати, які вже були збережені раніше.

## Як налаштувати AOR в адмін-панелі

1. Відкрийте **Адмін → Населені пункти AOR**.
2. Знайдіть потрібну смугу відповідальності.
3. У полі **Файли settlements.json** виберіть усі регіони, які покриває AOR, та сусідні регіони, згадки з яких реально трапляються в роботі.
4. Натисніть **Зберегти**.

Той самий вибір доступний у розділі **Адмін → Смуги** через дію **Обрати файли населених пунктів** біля потрібного AOR.

Порожній вибір означає **набір сервера за замовчуванням**, а не відсутність населених пунктів. Не варто вибирати всі регіони без потреби: це підвищує ризик неоднозначних збігів.

## Звідки беруться файли

Регіональні файли надходять із `milgeo-rs` і в репозиторії ECHO лежать у:

```text
wdintel-rs/data/settlements_json/
```

Під час встановлення пакета вони копіюються на сервер у:

```text
/etc/echo/settlements_json/
```

Адмін-панель автоматично показує всі файли з цього каталогу з розширенням `.json`. Щоб додати або оновити регіон, потрібно замінити відповідний файл версією, згенерованою в `milgeo-rs`, доставити його разом з оновленням ECHO та перезапустити ECHO. Редагувати великий JSON вручну не рекомендується.

Після перезапуску перевірте, що новий файл з’явився в **Адмін → Населені пункти AOR**, і виберіть його для потрібних AOR.

## Що таке `settlements_sources`

`settlements_sources` — це параметр сервера у `/etc/echo/config.toml`. Він задає, які регіональні файли утворюють **набір населених пунктів за замовчуванням**. Це потрібно для обробки без відомого AOR і як запасний варіант для AOR без власного вибору.

`settlements_sources` не обмежує перелік файлів в адмін-панелі. Адмін-панель показує всі регіональні `.json` із каталогу `settlements_json/`, а параметр визначає лише набір за замовчуванням.

Правило вибору просте:

| Ситуація | Які файли використовує ECHO |
| --- | --- |
| Для AOR явно вибрано один або кілька файлів | Файли, вибрані в адмін-панелі для цього AOR |
| Для AOR залишено «Набір сервера за замовчуванням» | Набір із `settlements_sources` або старий спільний файл, якщо параметр порожній |
| Під час обробки AOR невідомий | Набір із `settlements_sources` або старий спільний файл, якщо параметр порожній |

У параметрі вказують назви регіональних файлів без каталогу та `.json`, через кому:

```toml
settlements_sources = "kharkivska_oblast, sumska_oblast, bilhorodska_oblast_rf"
```

ECHO прочитає це як файли:

```text
settlements_json/kharkivska_oblast.json
settlements_json/sumska_oblast.json
settlements_json/bilhorodska_oblast_rf.json
```

Порядок назв у параметрі не має значення. Назви мають точно відповідати файлам у `/etc/echo/settlements_json/`. Якщо назва помилкова або файл пошкоджений, ECHO зупинить запуск із помилкою замість роботи без довідника населених пунктів. Після виправлення `config.toml` або файлу потрібно перезапустити ECHO.

Якщо `settlements_sources` відсутній або порожній, для сумісності зі старими встановленнями набір за замовчуванням береться зі спільного файлу `/etc/echo/settlements.json`. Це застарілий формат, де багато регіонів зібрано в одному файлі. Порожнє значення параметра не означає «не використовувати населені пункти».

Для окремих AOR слід використовувати регіональні файли з `settlements_json/` через адмін-панель. Змінювати `settlements_sources` щоразу при зміні одного AOR не потрібно: параметр є загальним fallback-набором для всього сервера.

## Практичний приклад

Якщо AOR охоплює схід Харківської області та ділянку біля кордону, доцільно вибрати:

- `kharkivska_oblast.json`;
- `sumska_oblast.json`, якщо в даних трапляються згадки із сусідньої Сумщини;
- `bilhorodska_oblast_rf.json` і `kurska_oblast_rf.json`, якщо робоча зона або повідомлення охоплюють прикордонні території РФ.

Точний набір визначається реальною географією AOR, а не лише назвою основної області.
