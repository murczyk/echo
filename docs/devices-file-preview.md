# Перегляд файлів пристроїв

У вкладці **Файли** виберіть файл із дерева або результатів пошуку. Перегляд і скачування прив’язані до конкретної ревізії, включно з історичною сесією синхронізації. Потрібен чинний доступ на читання пристрою. Окрема вкладка **Аудіо**, FileSync і TUS зберігають свої попередні контракти.

| Категорія | Формати | Можливості |
| --- | --- | --- |
| Документи й таблиці | TXT, MD, Markdown, PDF, DOC, DOCX, XLS, XLSX, CSV | Текст, сторінки PDF, аркуші, масштаб 50–300% |
| Зображення | JPG, JPEG, PNG, GIF, WebP, BMP, SVG | Масштаб, переміщення, повноекранний перегляд; SVG відкривається як зображення |
| Аудіо | MP3, MPEG, MPGA, WAV, OGG, OGA, Opus, M4A, AAC, FLAC, WebM | Відтворення, пауза, перемотування й гучність |
| Відео | MP4, M4V, MOV, WebM, MKV, AVI, MPEG, MPG, WMV, FLV, F4V, 3GP, 3G2, M2TS, OGV, VOB, ASF | Відтворення, перемотування, масштаб і переміщення |
| Архіви | ZIP | Папки в дереві; вкладені каталоги, прев’ю та скачування окремих файлів |
| Мапи | KML, KMZ | Геометрія на мапі без Alpine |
| Мапи з підготовкою | GPX, GeoJSON, LDK, TRK, ARE, RTE, WPT, SET, FIT | Підготовка через наявний Alpine, потім перегляд KMZ |

Використовуються ті самі переглядачі й парсери, що на сторінках оперативного та аналізу. Підтримка контейнера аудіо/відео не гарантує підтримку його кодеків браузером: за неможливості відтворення показується пояснення і залишається скачування оригіналу. MIME може визначити категорію без суфікса; для неоднозначних MPEG/WebM враховується збережений MIME. DOCX/XLSX/KMZ із ZIP MIME зберігають спеціалізований перегляд.

Порожній файл, відсутній контент, пошкоджений документ, перевищення ліміту або захищений ZIP мають окремі видимі стани. Оригінал можна скачати, якщо контент існує і доступ дозволений. Зміна файлу, закриття чи виявлена відмова доступу скасовує запити, завершує парсери й зупиняє медіа. Повторна спроба доступна для тимчасових помилок.

ZIP у дереві розгортається як папка. Вкладені файли відкриваються в тій самій панелі перегляду; вкладені ZIP також розгортаються. DOCX/XLSX/KMZ залишаються спеціалізованими документами чи мапами. Перелік читається при розгортанні, а вибраний файл розпаковується в пам’яті після повторної перевірки доступу до ревізії архіву. Пошук і лічильники FileSync охоплюють зареєстровані файли, а не віртуальні елементи ZIP.

Обмеження ZIP: 25 MiB на архів кожного рівня, до 1000 записів/рядків переліку, 200 MiB сумарного розпакованого обсягу на архів, 50 MiB на файл, до восьми рівнів вкладення. Небезпечні шляхи, шифровані чи непідтримувані записи не відкриваються. Blob URL вибраного файлу звільняється при зміні вибору, закритті або відмові доступу й не потрапляє до загального кешу документів.

## Серверні маршрути

`R = /api/device/files/{device_id}/{file_id}/revisions/{revision}`.

| Метод і шлях | Призначення |
| --- | --- |
| `GET`, `HEAD R/content` | Оригінал: attachment, octet-stream, незмінні байти |
| `GET`, `HEAD R/preview/media` | Аудіо/відео: inline, канонічний MIME і підтримка одиночного byte range |
| `GET R/preview/geodata` | Статус; читання не створює завдання |
| `POST R/preview/geodata` | Ідемпотентна підготовка без тіла запиту |
| `POST R/preview/geodata/retry` | Повторна підготовка з `expected_generation` |
| `GET`, `HEAD R/preview/geodata/{generation}/content` | Готовий KMZ конкретної чинної generation |

Для картографічного елемента ZIP усі geodata-маршрути приймають `?archive_members=3,1`: послідовність індексів записів центрального каталогу від зовнішнього архіву до вибраного файлу. Ідентичність завдання включає цю послідовність; різні елементи однієї ревізії мають незалежні generation і результати. Worker перевіряє SHA оригіналу, розпаковує вибраний елемент з обмеженнями ZIP і передає його наявному Alpine. Права й актуальність generation перевіряються також при читанні результату.

Усі маршрути перевіряють доступ на читання і повертають `private, no-store`. Для media `HEAD` читає лише метадані. Один коректний `Range` повертає 206 або 416; некоректний, множинний чи запит із `If-Range` повертає повний вміст без validator. Перед встановленням native media src клієнт перевіряє `GET Range: bytes=0-0`.

Перевірки доступу через `HEAD` обмежені 20 секундами. Завантаження зображення разом із читанням тіла відповіді обмежене 75 секундами. Таймаут скасовує запит, показує помилку та залишає доступною кнопку «Повторити»; зміна вибраного файлу скасовує попередню спробу.

## Ресурси й експлуатація

Максимальний розмір завантаження — 20 ГіБ. Файлова система upload-spool повинна мати місткість щонайменше 82 ГіБ: загальний бюджет резервувань 80 ГіБ і резерв вільного місця 2 ГіБ. Бюджет на один логін — 100 ГіБ; його завантаження також обмежені загальним бюджетом 80 ГіБ. Ліміти задано константами в `wdintel-rs/src/devices/config.rs`; секція `[device_file_content]` у TOML не використовується.

Після успішного завантаження в S3 і публікації ревізії перевірений оригінал зі spool зберігається в наявному дисковому кеші медіа. Пристрої, оперативний та аналіз використовують спільні ліміти й очищення. Кеш вмикається в **Адміністрування → Системні налаштування → Кеш**; стандартне утримання — 24 години. Окремого перемикача пристроїв немає. S3 залишається постійним сховищем; нестача місця або збій кешу не скасовує успішну публікацію. Спроба доступу до кешу обмежена п’ятьма секундами, після чого читання переходить до S3, а публікація завершується без кешування.

Скачування, media Range, конвертація геоданих і витяг документів спочатку читають цей оригінал. Кеш переживає перезапуск API і доступний процесам зі спільним `storage_dir`, S3 endpoint та bucket. Перед видачею байтів HTTP-маршрути перевіряють доступ і точну ревізію. Якщо процес зупинився після commit до захоплення spool, наявний cleanup worker повторює захоплення для завершеного upload перед видаленням spool. Ревізії, для яких spool уже видалено до цього оновлення, автоматично не прогріваються; за відсутності кешу працює попереднє читання S3.

За відсутності утриманого оригіналу шифроване медіа до 100 MiB дешифрується в приватний кеш окремого API-процесу: максимум 1 GiB/128 записів, резерв вільного місця 1 GiB, single-flight population до 65 секунд. Права каталогів 0700, файлів 0600. Потік утримує lease; cleanup не видаляє його файл. Клієнт допускає 75 секунд на підготовку, завантаження або seek, тому попередня перевірка і відтворення можуть потрапити до різних API-процесів. Plaintext S3 читається потоком потрібного діапазону.

Geodata використовує таблицю `file_preview` в **wd_files** і наявний bgworker. Перед запуском нової версії застосуйте стандартні міграції `just migrate-all-up <mode>`. Конвертація потребує налаштованих file registry, приватного S3 та Alpine; при відсутності Alpine інші категорії продовжують працювати. Cleanup потребує registry/S3 і працює незалежно від Alpine.

Межі конвертації: source 200 MiB, KMZ result 25 MiB, одна активна конвертація на wd_files database, 128 pending globally/16 на пристрій, до трьох автоматичних спроб. Підготовка має lease, heartbeat і перевірку generation перед публікацією. Готовий результат живе сім днів; видалені чи замінені результати прибираються з повторним видаленням для пізнього PUT. Оригінал не змінюється.

Після двох хвилин клієнт припиняє автоматичне опитування і пропонує **Перевірити стан**. Це не створює дубль завдання. **Повторити підготовку** доступне для retryable failure після cooldown; 409 оновлює статус. Відсутність Alpine/S3 повертає 503, переповнення черги — 429, завеликий source — 413. Перевіряйте журнали bgworker та метрики `echo.device_files.preview.events.count`, queue age і журнали media cache; внутрішні storage keys не повертаються в UI.

## Локальна перевірка

`scripts/devices/test-file-preview.sh setup` створює власні loopback API A/B, bgworker, frontend, Redis, MinIO та окремі бази зі стандартного test dump. Скрипт виводить приватний каталог запуску; використовуйте його `environment.sh`, потім `scripts/devices/test-file-preview.sh seed --root <root>`. У `wdintel-web` спочатку запустіть `npx playwright test tests/e2e/device-file-preview-media-reference.spec.ts --project=chromium --workers=1`, потім `npx playwright test tests/e2e/device-file-preview-*.spec.ts --project=chromium --workers=1`. Порівняння медіа потребує результатів еталонного перегляду саме цього запуску; вони зберігаються у приватному `<root>/acceptance-media/reference-outcomes.json`. Окремі тести керування, доступу й життєвого циклу медіа не потребують цього артефакту. Маршрутизацію двох API змінює `route --root <root> --api a --media-preflight a --media-stream b`. Завершуйте власне середовище через `teardown --root <root>`.

`python3 scripts/devices/file_preview_media_resources.py --root <root> --exhaust` перевіряє потоковий plaintext 2 GiB, encrypted 100 MiB, SHA, Range, RSS та вичерпання/відновлення кешу на штучних байтах. Це ресурсна перевірка, не перевірка кодеків; виконуйте її окремо від браузерних тестів. `scripts/devices/test-file-preview.sh faults --root <root>` перевіряє реальні збої локального worker, втрату підтвердження commit і cleanup через тестові HTTP/PostgreSQL проксі. Її mock Alpine повертає контрольний KMZ і не доводить підтримку форматів конвертером.

Локальні HTTP-boundary tests Alpine перевіряють тайм-аути, обмеження і пошкоджені відповіді. Підтримку всіх дев’яти форматів необхідно окремо перевіряти з живим Alpine і справжніми файлами відповідних форматів; fallback чи тестовий HTTP server цього не доводить.
