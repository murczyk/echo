# Ролі та права доступу

Ролі додають права одна до одної. Обмежена роль не скасовує дозволи іншої
призначеної ролі. Назви чутливі до регістру; `CyberViewerRestricted` записується
латиницею. Ролі користувача зберігаються в JSON `login.roles`, тому додавання
нової ролі не потребує міграції або зміни згенерованих API-типів.

## Успадкування

Серверний контракт: `wdintel-rs/src/users/mod.rs`, `role_matches`.
Відповідники UI: `wdintel-web/src/Core/Auth.elm` та
`wdintel-web/src/ts/react/utils/roles.ts`.

| Призначена роль | Додаткові ефективні ролі | Основне призначення та межі |
| --- | --- | --- |
| `Basic` | — | Конвертери, термінал, доступні джерела та їхні групи, події; не відкриває оперативний/аналітичний інтерфейс або пристрої. |
| `CyberViewerRestricted` | `Basic` | Усі спільні права `CyberViewer` поза пристроями: оперативний перегляд, аналіз, відповідні довідники, звіти та AI за їхніми додатковими умовами. Без пристроїв, їхніх файлів, аудіо, документів, FileSync і довідника назв пристроїв. |
| `CyberViewer` | `CyberViewerRestricted`, `Basic` | Також перегляд пристроїв, створення пристроїв, зміна `external_url`/`custom_fields`, FileSync, читання та прослуховування аудіо. Не надає редагування повідомлень, аналітичних полів пристроїв, завантаження аудіо або зміни його тексту/статусу. |
| `Cyber` | `CyberViewer`, `CyberViewerRestricted`, `Basic` | Додає запис повідомлень, аналітичних полів пристроїв (`name`, підрозділ, смуги), завантаження та редагування аудіо. Не надає радіоінтерфейс `Rer`. |
| `Rer` | `Basic` | Оперативний/аналітичний і радіоінтерфейс, створення та редагування повідомлень. Самостійно не дає пристроїв або видалення повідомлень. |
| `Bpla` | `Basic` | Спеціальні операції БпЛА, зокрема відповідні Delta/KML/ATAK-конвертації. Не успадковує `Rer`. |
| `Full` | `Rer`, `Bpla`, `DeleteMsg`, `Basic` | Сукупність цих прав; не дорівнює `Admin`, не дає пристроїв, редакторських ролей або `AdvancedReports`. |
| `DeleteMsg` | — | Дозволяє видалення повідомлень; не відкриває інші розділи самостійно. |
| `UnitsEditor` | — | Дозволи редагування підрозділів, мереж та їхніх зв'язків у відповідних API; для частини операцій також потрібний базовий доступ до аналізу. |
| `CallsignsEditor` | — | Редагування словника позивних; також допуск до спеціальних видів звітів. |
| `NetworkEditor` | — | Роль збережена в ієрархії та адміністративному виборі; окремих активних перевірок цієї ролі в API/UI немає. Редагування мереж перевіряє інші права, зокрема `UnitsEditor`. |
| `AdvancedReports` | — | Доступ до спеціальних видів звітів разом із необхідним доступом до відповідного API. Такий допуск також мають `UnitsEditor`, `CallsignsEditor`, `Admin`. |
| `CyberMessengers` | — | Додаткова роль: перегляд акаунтів месенджерів, їхніх чатів, учасників і повідомлень та редагування внутрішніх нотаток акаунта через `/api/messengers`. Потребує також `Rer` або `CyberViewerRestricted` і доступу до групи акаунта; сама по собі нічого не відкриває. |
| `Api` | — | Доступ лише до API, які явно допускають цю роль; спеціальний спільний rate limit, пропуск TOTP. Не дає автоматично пристроїв або всіх користувацьких API. |
| `ApiAgent` | — | Службова роль AI-агента, явні дозволи API та пропуск TOTP; керовані агенти додатково обмежені allowlist, прив'язкою до людини та сесійними дозволами. Людський AI-інтерфейс для цієї ролі заборонений. |
| `NoAutoLogout` | — | Виняток з автоматичної деактивації користувача за тривалою неактивністю. Не надає доступу до даних. |
| `No2FA` | — | Пропуск TOTP. Не надає доступу до даних. |
| `Admin` | Усі перелічені, крім `Api`, `ApiAgent`, `NoAutoLogout`, `No2FA` | Адміністративні API та успадковані прикладні дозволи. Обмеження видимості даних та налаштування функцій перевіряються окремо. |

`DeviceSource` — застаріла роль, яка не надає актуальних дозволів. Історична
міграція `m20261006_110425_merge_cyber_roles` переписала старі призначення
`DeviceSource`/`CyberViewer` на `Cyber`; вона не змінюється при додаванні
`CyberViewerRestricted` і не відновлює колишні призначення.

## Роль не є повною політикою доступу

- `ensure_basic_role` перевіряє `Basic`; `ensure_base_role` перевіряє ефективну
  `Rer` або `CyberViewerRestricted`. Це різні рівні доступу.
- Видимість повідомлень визначають також групи користувача; пристроїв — його
  організм і дочірні організми. Налаштування системи, архівність, власник
  об'єкта та спеціальні дозволи конкретної операції залишаються чинними.
- Ролі з назвою Viewer не є глобальним режимом «тільки читання»: дозволені,
  наприклад, власні фільтри, закладки та позначки важливості. Новій ролі
  збережено всі такі дозволи `CyberViewer` поза пристроями.
- Прихована радіонавігація не дорівнює забороні всіх радіо-API: частина API
  частот, сигналів і мереж допускає базові ролі перегляду. Нова роль має тут
  ті самі дозволи, що й `CyberViewer`.

## Межа доступу до пристроїв

`wdintel-rs/src/devices/access.rs` залишає дозволи пристроїв тільки за
`CyberViewer`, `Cyber`, `Admin`; для запису аудіо та аналітичних полів —
тільки `Cyber`, `Admin`. Спільні API перегляду використовують окремий дозвіл
`CyberViewerRestricted`, який успадковується старими cyber-ролями.

Перевірка охоплює:

- списки, картки, статистику, створення та зміни пристроїв;
- дерево, пошук, історію, вміст, завантаження, перегляд та синхронізацію файлів;
- список, деталі, потоки аудіо, транскрипцію і налаштування аудіо;
- документи пристроїв і виклики AI через `devices/documents/access.rs`, які
  перевіряють актуальні права прив'язаного користувача;
- назви пристроїв, фільтри та відповідні поля повідомлень через
  `require_message_devices`. Для керованого AI-агента тут також перевіряються
  права людини, а не його технічна роль `Cyber`;
- меню React і прямі маршрути Elm `/devices` та `/devices/:id`.

Поєднання `CyberViewerRestricted` + `CyberViewer`/`Cyber`/`Admin` знову дає
пристрої. Поєднання з `Rer`, `Full`, `Basic` або редакторськими ролями
самостійно доступу до пристроїв не додає.
