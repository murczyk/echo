Goal

Provide the application metrics needed to recreate existing Discord operational alerts in SigNoz. Reuse Echo’s existing OTLP exporter, already used on CBR.

Required changes

Add these metrics:

Metric | Required detail -- | -- Datasource activity age | Per datasource; preserve the timestamp selection and fallback logic currently used by /api/monitoring Root filesystem available space | Available bytes on / Messenger account linkage | Explicit linked/unlinked state per account Signal/REST API errors | Counters distinguishing timeouts from other errors, grouped by client/account Report timeouts | Counter grouped by report kind

Reuse the existing queue depth, queue age, processing outcome/latency, and NLP readiness metrics.

Requirements

  • Export through the existing signoz_metrics_enabled and signoz_metrics_endpoint configuration.
  • Include consistent installation and datasource/account identifiers.
  • Publish state metrics periodically, including healthy states.
  • Distinguish collection failures from healthy or zero values.
  • Define behavior for paused/deleted accounts and datasources.
  • Keep message contents, credentials, and phone numbers out of metric labels.
  • Document metric names, units, labels, update intervals, and which existing Discord conditions they support.

Acceptance criteria

  • Metrics are queryable in SigNoz when the exporter is enabled.
  • Datasource freshness values match /api/monitoring for the same datasource and observation time.
  • Tests cover healthy, failed, recovered, and unavailable states.
  • Every application-generated operational Discord alert is mapped to an exported signal; any remaining gaps are explicitly listed.
  • Existing Discord notifications remain enabled during this development task.
