# Impeccable for Echo

This is an [adapted Markdown subset](NOTICE.md) of Impeccable, not its runtime.
Read `PRODUCT.md`, `DESIGN.md`, the layout contract and the affected surface's
instructions from the Git root. Preserve the assigned task, evidence and scope.

| Need | Reference |
| --- | --- |
| Clarify outcomes, navigation, scenarios and layout | [Shape](reference/shape.md) |
| Review usability, hierarchy and cognitive load | [Critique](reference/critique.md) |
| Inspect accessibility, responsiveness and implementation risks | [Audit](reference/audit.md) |

Read only the relevant reference. Use source files and an already available,
authorized synthetic preview; report unavailable rendered checks explicitly.
Use simple SVG blocks or Mermaid for an assigned wireframe. A diagram, source
review or screenshot alone does not prove interactions or human usability.

This skill creates design documents or review findings, not product code or
executable tests. It does not launch stages, delegate to agents, install tools,
start services, inject overlays, publish data or change personal settings.
The repository package has no launcher, detector, hooks or agent definitions;
do not fetch them or substitute a personal runtime to complete this reference.
Use synthetic/redacted data and respect existing external-data permissions.

Echo components, tokens, behavior contracts and approved decisions take
precedence over generic design advice. Keep assumptions distinct from evidence;
relay material questions through main when assigned to a managed role.
Return the target, findings/decisions, artifact paths, checks and remaining gaps,
then stop at the requested deliverable. Approval and implementation remain
separate stages under the explicitly requested Echo workflow.
