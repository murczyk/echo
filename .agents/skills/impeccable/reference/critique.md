# Critique

Echo adaptation of Impeccable's `critique` reference; see [source notice](../NOTICE.md).
Review how well one concrete surface or flow supports the assigned user task.
Use a single scoped assessment; this reference does not dispatch other agents.

## Establish the evidence

Resolve a route/component and the relevant state, theme and viewport. Read the
task, contracts and source. Inspect an already available authorized synthetic
preview when possible; otherwise label the assessment as source-only.
Separate observed behavior, source evidence, interpretation and open questions.
Do not turn a missing browser or an untested state into a pass.

## Evaluate the user task

| Heuristic | What to inspect |
| --- | --- |
| Visibility of system status | Selection, progress, loading, stale data, success and errors are understandable. |
| Match to the user's work | Language, ordering and grouping fit the actual task and domain. |
| User control | Back, cancel, dismissal and recovery preserve appropriate context. |
| Consistency | Similar actions and states use established patterns across affected surfaces. |
| Error prevention | Constraints and risky actions are explained before failure; permissions remain enforced. |
| Recognition over recall | Required facts, active filters and consequences remain visible where decisions are made. |
| Efficiency | Frequent work avoids unnecessary navigation and repeated entry; shortcuts do not hide basic actions. |
| Visual hierarchy | Primary information/actions are discoverable without making every element compete. |
| Error recovery | Messages explain what happened and the next action; input and useful state survive. |
| Contextual help | Necessary explanations appear near the decision without overwhelming experienced readers. |

Apply relevant heuristics rather than inventing findings for every row. Preserve
patterns that work. For Echo's dense information surfaces, prefer legibility,
predictable actions and continuity over decorative novelty.

## Cognitive load and layout

- Group related information and choices; expose secondary controls when useful.
- Keep information needed for a decision together rather than requiring memory
  across screens, tabs or modals.
- Make location, selection, filters and navigation destinations apparent.
- Use familiar Ukrainian labels and explain necessary domain terms in context.
- Check reading order, long content, empty states, visual emphasis and repeated
  rows; do not remove useful density just to make the screen look simpler.
- Check keyboard/focus paths and interruption/recovery as well as the happy path.
- Examine shared consumers before recommending a new variant or interaction.

Use actual product users and scenarios; do not invent personas, abandonment
rates or user-test results. A heuristic score is not a usability measurement.

## Return actionable findings

For each material finding, state severity, affected scenario/state, file or
observed location, evidence, user impact and a concrete scoped recommendation.
Distinguish a task blocker, a serious difficulty, a recoverable annoyance and
optional polish. Keep minor findings few and identify useful behavior to preserve.

End with unresolved decisions and the next check that could validate the
recommendation. Use the agreed task evidence/artifact location; do not create a
separate critique database or start fixes, setup, publication or another stage.
Report exactly what was inspected and what remains unverified.
