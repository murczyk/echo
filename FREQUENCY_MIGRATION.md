2. Оновити файли проекту до останньої версії
3. (Опційно) Виконати перевірку та чеки для міграції на базі, що б уникнути помилок і непередбачених ситуацій. Якщо ок, то продовжуємо. Перевірку можна виконати такою командою: `cargo run -p wdintel-rs -- --mode debug oneoff-migrate-modulation-to-encryption --dry-run`
4. запустит бек і фронт і переконатися, що вони працюють. (При цьому на юай шифрування відображатися буде як null або порожні, це пов'язано з тим що для шифрування буде інша таблиця, і після міграції даних через команду `oneoff` почне нормально тягнути шифрування з бази)
5. (бажано на цьому етапі знову виконати перевірку міграції) → Виконати перевірку міграцію через `oneoff команду: cargo run -p wdintel-rs -- --mode debug oneoff-migrate-modulation-to-encryption --dry-run`. Та детально буде виведено які дані у які будуть мігрувати. Якщо все влаштовує, то можна переходити до наступного кроку.
6. Виконати міграцію через `oneoff` команду: `cargo run -p wdintel-rs -- --mode debug oneoff-migrate-modulation-to-encryption`
7. (бажано) перевірити, що відповідні зміни присутні в базі, 'encryption' таблиця є — це оснований маркер, на цьому етапі можна знову запустити команду міграції або драй-ран міграції та побачити, що кількість рядків для зміни `0`, повинна бути само `0`, якщо не `0` то міграція можливо була не успішна.
8. спробувати на юай зайти й перевірити мережі, конкретну мережу, частоти в мережі, спробувати поредагувати або створити частоту та ключ для неї
Команди:

Перевірка можливості міграції - `cargo run -p wdintel-rs -- --mode debug oneoff-migrate-modulation-to-encryption --dry-run`
Запуск самої міграції - `cargo run -p wdintel-rs -- --mode debug oneoff-migrate-modulation-to-encryption`

Примітка: прочитати обов'язково
Після `DDL` міграції, але перед тим як `oneoff` команда виконана, нове поле `modulation` ставиться в значення `NFM` як дефолтне, а `ecnryption_id` на цей час буде `null`, а UI уже заточений на відображення нових полів, і на цей час юай буде відображати відповідні дефолтні значення. Після виконання `oneoff` команди для міграції даних, ці нові поля заповняться і юай буде відображати актуальней стан правильно.
