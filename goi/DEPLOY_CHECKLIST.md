# ЧЕКЛІСТ
> Це чекліст розгортання нового GOI інстансу.
Чергу розгортання серверів ведемо В [гугл табличці](https://docs.google.com/spreadsheets/d/1o24HbY8i7PG0Y0ZAXU47iGuU67Q4LIwpj99FxCLCJ5I). З неї починаємо процес (обираємо наступний сервер на розгортання), нею ж закінчуємо (актуалізуємо - вносимо деталі доступів).

- Згідно інструкції з `GOI_CONTAINER.md`
  - генеруємо код в обліковому записі тейлскейл echo-goi@outlook.com
  - клонуємо контейнер goi-stg. Назва тачки: наприклад goi-159ombr
- команда клонування по закінченні друкує SSH конфіг, потрібно додати його в [ЕХО сержант](https://github.com/echoua/echo-sergeant), у файл `ssh/config`, поруч із іншими goi інстансами
- Після створення нового контейнера вносимо правки в обліковому записі Tailscale: 
  - disable key expiry
  - генеруємо інвайт, приймаємо з під ЕХО tailscale юзера (наприклад з під ЕХО ПІВНІЧ)
  - генеруємо Tailscale ПЕРМАНЕНТ ІНВАЙТ на ГОІ контейнер для самих користувачів
- додати УРЛ таі нші деиталі в гугл доку
- на веб інтерфейсі насетапити новий ГОІ
    - адмін->goi: нова інтеграція
    - взяти з /etc/echo-goi-worker/config.toml логін пароль
    - зберегти - перевірити зʼєднання -- показало шо треба інвайт
- покласти SSH-ключ в authorized_keys відповідного ЕХО-напрямку
- редеплой свіжої версії
	- just -f ./goi/justfile deploy --server="..."
- скинути користувачеві який вказаний в гугл доку інструкцію на вхід і посилання
